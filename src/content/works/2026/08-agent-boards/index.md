## 概要

エージェントに画像や文章やレポートを作らせると、結果はファイルとして手元に残るが、1 つずつ開いて確かめ、直してほしい所を会話に書き直すのは手間がかかる。agent-boards では、エージェントが結果を窓で開き、人はその窓の中で見比べ・書き込み・指示をする。

| 窓 | 見せるもの |
| --- | --- |
| moodboard | 画像・動画・音声を並べて見比べ、残すものを選ぶ |
| textboard | テキストファイルを直接直し、コメントを付け、エージェントに指示を送る |
| reportboard | Markdown のレポート(計測・調査・見積もり)を決まった体裁で読み、節ごとにエージェントに直させる |

2026/08 に[路地裏あやかし合戦](/blog/works/2026/06-ai-ayakashi-kassen/)で生成画像を見比べるために書いたビューアを moodboard として切り出し、2026/10 に textboard を作った。同じ月に reportboard を足し、3 つを agent-boards の 1 リポにまとめた。

## moodboard

AI が生成した画像・動画・音声を、ライトテーブルの写真のように 1 つの窓に並べる。

- 画像(PNG / WebP / アニメーション GIF)はピクセル単位まで拡大でき、2 枚を重ねて比べられる。背景を市松模様にして透過も確かめられる
- 動画(mov / webm / mp4)は並べた状態では無音でループ再生し、拡大表示で音つきで見られる。拡大表示には再生・シークの操作バーが付く
- 音声(wav / mp3 / m4a / aac / flac / ogg / opus)は 1 ファイル 1 枚のプレイヤーカードになり、テイクを順に聞き比べられる
- エージェントはまとまりごとの見出しと、カードごとのラベル(「案 A」「テイク 2」など)を付けられる
- 選択モードで選んだカードのファイルパスをクリップボードにコピーし、会話に貼って選んだものを伝えられる

## textboard

エージェントが書いた README・記事・仕様などのテキストを、人と一緒に直すための窓。AI は組み込んでおらず、窓を開いたエージェントが書き直す。

- Markdown はソースのまま表示し、窓の中で直接直して保存できる
- 選んだ箇所にコメントを付けられる。エージェントがファイルを書き直しても、コメントは引用した文と前後の文から元の箇所を探し直す。見つからないコメントは件数を出して一覧にする
- 窓の下の欄から指示を送ると、エージェントがコメントと行番号と一緒に受け取る
- 窓で直している途中に外でファイルが変わったときは、外の版を読み込むか自分の版で上書きするかを選ぶ
- コメントはリポではなく `~/.textboard/` に保存する

## reportboard

エージェントが Markdown で書いたレポートを、決まった体裁で表示する窓。

- `##` の見出しから目次を作る。「名前 — 数値 単位」が並ぶリストは、数値を大きく出して棒で比べる内訳になる。単位のそろった表の列は右寄せにして棒を付け、合計の行は太字にする
- エージェントがファイルを書き換えると 1 秒以内に読み直し、前の版から変わった行や段落に印を付ける
- 節の見出しと内訳の各行に「AI と直す」があり、その場で直し方の指示や質問を送れる。エージェントは Markdown を直して、何を変えたかを同じ欄に返す。やり取りはチャットの形で残り、レポートを書き換えても見出しや行についていく
- エージェントがメッセージを受け取ったか、まだ作業中かが欄に出る

## 3 つに共通すること

- 名前を付けた窓を使い回し、同じ作業では新しい結果が前の結果と入れ替わる
- 開くコマンドは窓が中身を読み込むまで待ってから終わり、終了コードで本当に表示できたかがエージェントに分かる
- 画面とメッセージは日本語・英語に対応
- エージェントへの使い方は Agent Skills 形式のスキルとして配布する。セットアップは `bun install -g github:mohhh-ok/agent-boards` と `npx skills add mohhh-ok/agent-boards` の 2 行
- 窓は外部依存のない HTML を webview-bun(WKWebView)で開くだけで、ブラウザは使わない

動作環境は macOS のみ(macOS でだけ確認)。
