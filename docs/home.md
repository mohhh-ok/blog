# ホーム（/blog/）の構成

ホームに来るのは、記事を読んだあとに「この人は誰か」を見に来る人と、仕事を頼むか考えている人。ホームは「何者で、何を作れるか」を一目で見せることに絞る（2026-11 ユーザーと決定）。

## 構成（上から）

1. ヘッダー（既存のまま）
2. 自己紹介（見出しなし）
   - 1 段落目: フリーランスエンジニアの moh であること。TypeScript を中心にした Web フルスタック、Chrome 拡張・デスクトップアプリを作っていること、AI 活用の相談を受けていること
     - 続けて、仕事の相談は X（https://x.com/masaakiotadev ）の DM で受けていることを 1 文で書き、リンクは新しいタブで開く（2026-11 ユーザーが決定）
   - 2 段落目: 2026 年 2 月から AI エージェントを実装の主力にしていること、設計判断は人が行うこと（今の「AI活用」節の中身を 1〜2 文に詰める。「AI活用」の見出しは置かない）
3. 作ったもの（見出し `作ったもの`）
   - Works のうち `featured` を付けた作品をカードで並べる。並び順は `featured` の数字の小さい順
   - カード 1 枚: hero 画像（Works 一覧のカードと同じ 16:9 で切り抜き）、作品名、summary（2 行で切る）、期間。カード全体が作品ページ（/blog/works/…/）へのリンク
   - PC は 2 列（4 作品で 2 行）、SP は 1 列
   - カードの下に「すべての作品を見る」（/blog/works/）。ホームでいちばん目立たせる操作はこれ 1 つ
4. 最近の投稿（見出し `最近の投稿`）
   - 新しい順に 8 件。各行は日付と記事名
   - 下に「すべての記事を見る」（/blog/posts/）
5. ライブラリ（見出しなし、1 行）
   - 「TypeScript のライブラリや Claude Code のスキルも GitHub で公開しています。」と GitHub（https://github.com/mohhh-ok ）へのリンク。個々のライブラリ名はホームに並べない
6. フッター（既存のまま）

本文の幅は固定しない（最大幅だけ決める）。SP 幅で横にはみ出さないこと。

## 載せる作品

works の frontmatter に `featured: <数字>` を付けた作品だけを載せる。付け外しと並び替えは frontmatter だけで行う。

## 見た目

- 色は AGENTS.md のブランドカラーに合わせる。カードの地は `#ffffff`（背景 `#f2f0ee` の上に置く）
- 見出しは既存のページの見出しと同じ部品・同じ見た目にする
- カードは押せる物に見せる（hover で変化）。説明文や期間は押せる物に見せない
- 型どおりの飾り（左に色の縦線、角丸ピルのボタン、番号付きの見出し、等幅のラベル）は使わない
